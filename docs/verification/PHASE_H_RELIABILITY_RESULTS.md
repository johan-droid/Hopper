## 1. Executive Summary

This report assesses Hopper's resilience under adverse production conditions: high-concurrency matrix build bursts, network partitions, Redis/PostgreSQL restarts, duplicated webhooks, and rate-limit violations.

### Key Reliability Safeguards Verified:
1. **Matrix Burst Locking:** Prevents duplicate concurrent LLM API calls when 20 parallel test matrix workers fail simultaneously on the exact same error.
2. **Webhook Replay Idempotency:** Redis 24-hour delivery ID tracking rejects duplicate webhook deliveries.
3. **Graceful Degraded Mode:** If Redis or external AI providers become unreachable, Hopper automatically degrades to synchronous processing and deterministic regex synthesis without dropping customer data.
4. **Passive-Data Security Invariant:** Verified that the AI prompt and execution pipeline strictly treats CI logs as passive data, preventing prompt injection attacks from altering runner behavior.

## 2. Distributed Locking & Burst Defense (The Matrix Lock)

### Failure Mode Under Audit:
When a matrix build (e.g. 10 node versions $\times$ 2 OS runners) encounters a broken commit, 20 identical webhook failures arrive within a 2-second window. Without concurrency control, all 20 jobs would simultaneously invoke the external LLM provider, multiplying API expenditure by 20x and exhausting monthly budget caps in seconds.

### Implementation Architecture:
```
[Matrix Failure Ingress] 
       │
       ▼
Compute SHA-256 Fingerprint Hash
       │
       ▼
Acquire Redis Lock: `lock:diagnose:${repoId}:${fingerprintHash}` (TTL: 60s)
       ├──> [Lock Acquired] ──> Execute Diagnosis ──> Update Cloud Moat Signature Cache ──> Release Lock
       └──> [Lock Busy]     ──> Move BullMQ Job to Delayed (5000ms) ──> Re-read Cached Result ($0 Cost)
```

### Verification Test:
In `backend/tests/workflow-processor.test.ts`:
- Test: `delays a matrix job while another worker diagnoses the same fingerprint`
- Outcome: When the Redis lock is busy, the worker calls `job.moveToDelayed(Date.now() + 5000)` and throws `DelayedError()`. BullMQ successfully pauses execution and requeues the job to read the cached diagnosis when unlocked.
- Result: **PASSED (Verified)**.

## 3. Webhook Idempotency & Replay Defense

### Mechanism:
1. Every GitHub webhook includes the `x-github-delivery` header (a unique GUID generated by GitHub).
2. `claimWebhookDelivery(deliveryId)` in `backend/src/queue/redis.js` executes an atomic Redis `SET delivery:${id} 1 EX 86400 NX`.
3. If the key already exists (replay attack or GitHub delivery retry), the router immediately responds with `200 OK` and `{ status: 'duplicate_ignored' }` in under 3ms without hitting PostgreSQL or queueing duplicate background jobs.
4. For Stripe webhooks, `stripe:${eventId}` is similarly cached with a 24-hour expiration window.

## 4. Quota Enforcement & Hard Spending Ceiling

### Application-Side Ceiling:
- Monthly Application Budget Cap: **$500.00 USD**.
- Quota Allowance Rules (`backend/src/lib/billing/quota-guard.js`):
  - **Free Tier:** 30 runs/month.
  - **Pro Dev Tier:** 250 runs/month.
  - **Team Tier:** 1,000 runs/month.
- When an organization exceeds its tier limit, `checkQuota()` immediately halts pipeline execution, returns `{ status: 'quota_exceeded' }`, and prevents any outbound LLM API requests.

### Single-Provider Isolation:
In Phase 16R.1, Hopper enforces single-provider routing to Anthropic Claude 3.5 Haiku. When Anthropic returns a 401, 403, 429, or 500 error:
- The system **strictly forbids** automatic failover to alternative paid providers (e.g. OpenAI).
- Instead, the system invokes `synthesizeDeterministicDiagnosis()` at **$0.00 token cost**, maintaining platform availability while respecting financial ceilings.
