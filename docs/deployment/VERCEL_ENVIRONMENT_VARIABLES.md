# Vercel Environment Variable Register

Authoritative list of every variable Hopper reads. Nothing outside this table is
required, and **no Cloudflare variable exists**.

- **Scope** — `BE` = backend/API function only, `FE` = frontend bundle (public), `Both`.
- **Env** — `Dev` (local), `Pre` (Vercel Preview), `Prod` (Vercel Production).
- **Secret** — `Yes` values must never appear in the frontend bundle, logs, or git.
- Set all variables in **Vercel → Project → Settings → Environment Variables**, per
  environment. Local development uses `backend/.env` and `frontend/.env`.

---

## 1. Runtime

| Variable | Purpose | Required | Scope | Env | Secret | Source |
|---|---|---|---|---|---|---|
| `NODE_ENV` | Runtime mode; enables production validation | Yes | BE | All | No | Vercel (`production` / `preview`), local `development` |
| `PORT` | Local HTTP port (ignored on Vercel) | No (3000) | BE | Dev | No | Local |
| `APP_URL` | Canonical app origin | Yes (Prod) | BE | All | No | Vercel domain |
| `FRONTEND_URL` | Frontend origin for absolute links/redirects | Yes (Prod) | BE | All | No | Vercel domain |
| `CORS_ALLOWED_ORIGINS` | Comma-separated origin allowlist. **Required in production**; wildcard is refused | Yes (Prod) | BE | Pre, Prod | No | Vercel domain(s) |
| `MAX_REQUEST_BODY` | Express JSON body limit | No (`1mb`) | BE | All | No | Default |
| `VERCEL_ENV` | Injected by Vercel (`production`/`preview`/`development`) | Auto | Both | All | No | Vercel |
| `VERCEL_REGION` | Injected function region (`bom1`) | Auto | BE | All | No | Vercel |

## 2. Database — Supabase PostgreSQL + pgvector

| Variable | Purpose | Required | Scope | Env | Secret | Source |
|---|---|---|---|---|---|---|
| `DATABASE_URL` | **Pooled** connection (Supabase pooler, port 6543) used by functions | Yes | BE | All | **Yes** | Supabase → Database → Connection pooling |
| `DIRECT_URL` | **Direct** connection (port 5432) used only for migrations/DDL | Yes (migrations) | BE | All | **Yes** | Supabase → Database → Connection string |
| `DB_POOL_MAX` | Max pool size per function instance | No (`10`) | BE | All | No | Tuning |

> Serverless rules: pooled URL for runtime, direct URL for `npm run migrate`.
> Never open a connection per request; the pool is created once per instance.

## 3. Durable queue — Vercel Queues + PostgreSQL outbox

| Variable | Purpose | Required | Scope | Env | Secret | Source |
|---|---|---|---|---|---|---|
| `QUEUE_STORE` | `postgres` (only valid production value); `memory` is tests only and throws in production | Yes | BE | All | No | Fixed |
| `QUEUE_TRANSPORT` | `auto` (publish when `VERCEL=1`), `vercel`, `off` (local) | Yes | BE | All | No | `auto` on Vercel, `off` locally |
| `COORDINATION_BACKEND` | `postgres` for rate limits/locks/dedup; `memory` refused in production | Yes | BE | All | No | Fixed |
| `QUEUE_DRAIN_BATCH` | Jobs claimed per cron drain | No (`10`) | BE | All | No | Tuning |
| `WORKER_CONCURRENCY` | Local polling worker batch size | No (`3`) | BE | Dev | No | Tuning |
| `QUEUE_STORE` memory guard | `QUEUE_STORE=memory` in production throws at boot | — | BE | — | — | Built-in |
| `CRON_SECRET` | Bearer token Vercel Cron sends to `/api/cron/queue-drain`; endpoint returns 503 when unset | Yes (Prod) | BE | Pre, Prod | **Yes** | Generated by you; Vercel injects it into cron calls |

> Vercel Queues authenticates via OIDC automatically — **no queue API key or
> credential variable is required**. Do not invent one.

## 4. Authentication — Supabase Auth

| Variable | Purpose | Required | Scope | Env | Secret | Source |
|---|---|---|---|---|---|---|
| `SUPABASE_URL` | Project URL; also derives expected JWT issuer (`<url>/auth/v1`) | Yes | BE | All | No | Supabase → API |
| `SUPABASE_JWT_SECRET` | HS256 verification secret (either this **or** the public key) | Yes* | BE | All | **Yes** | Supabase → API → JWT settings |
| `SUPABASE_JWT_PUBLIC_KEY` | RS256/ES256 verification key | Yes* | BE | All | No (public) | Supabase → API → JWT keys |
| `VITE_SUPABASE_URL` | Browser client URL | Yes | FE | All | No | Supabase → API |
| `VITE_SUPABASE_ANON_KEY` | Browser anon key (public by design; RLS is the boundary) | Yes | FE | All | No | Supabase → API |

\* Exactly one verification key must be present. Production boot throws if both
are missing.

**Never** place `SUPABASE_SERVICE_ROLE_KEY` in the frontend or in `VITE_*`.

## 6. AI providers

| Variable | Purpose | Required | Scope | Env | Secret | Source |
|---|---|---|---|---|---|---|
| `AI_PROVIDER` | Strict single provider: `openai`, `anthropic`, or `mock` | Yes | BE | All | No | You (`mock` by default) |
| `AI_MODEL` | Model id for the selected provider | Yes | BE | All | No | e.g. `gpt-4o-mini`, `claude-3-5-haiku-20241022` |
| `EMBEDDING_MODEL` | Embedding model; must stay 1536-dim for pgvector | No (`text-embedding-3-small`) | BE | All | No | OpenAI |
| `OPENAI_API_KEY` | OpenAI key (diagnosis + embeddings) | If `AI_PROVIDER=openai` | BE | All | **Yes** | OpenAI dashboard |
| `ANTHROPIC_API_KEY` | Anthropic key | If `AI_PROVIDER=anthropic` | BE | All | **Yes** | Anthropic console |
| `AI_MONTHLY_BUDGET_USD` | Monthly AI spend ceiling enforced by the ledger | No (`500`) | BE | All | No | Policy |
| `AI_REQUEST_TIMEOUT_MS` | Per-request timeout | No (`15000`) | BE | All | No | Tuning |
| `AI_RETRY_INITIAL_DELAY_MS` | Bounded retry base delay | No (`500`) | BE | All | No | Tuning |

> There is **no** `CLOUDFLARE_ACCOUNT_ID`, `CLOUDFLARE_API_TOKEN`,
> `CLOUDFLARE_WORKER_AI_URL`, `EMBEDDING_MODEL=@cf/...`. Those are retired.
> A deterministic fallback exists and its telemetry is always marked
> `provider: deterministic`, `isFallback: true` — it is never reported as a live
> AI diagnosis.

## 10. Environment separation matrix

| Variable group | Development (local) | Vercel Preview | Vercel Production |
|---|---|---|---|
| Database | local pgvector container | Branch/preview Supabase project **(recommended)** or staging schema | Production Supabase |
| Auth | local/dev JWT or dev project | Preview Supabase project | Production Supabase |
| GitHub App | dev app or same app | Same app (separate webhook secret recommended) | Production app |
| Stripe | unset (free validation) | Test mode keys | Live keys |
| AI | `mock` | `mock` (avoid spending on previews) | `openai`/`anthropic` |
| Queue | `QUEUE_TRANSPORT=off`, polling worker | `auto` (real Vercel Queues) | `auto` |
| `CRON_SECRET` | unset | set | set |

## 11. Secret handling rules

1. Server-side only: `DATABASE_URL`, `DIRECT_URL`, `SUPABASE_JWT_SECRET`,
   `GITHUB_APP_*SECRET`, `GITHUB_APP_PRIVATE_KEY`, `STRIPE_*SECRET*`,
   `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, `CRON_SECRET`.
2. Never prefix a secret with `VITE_` — Vite inlines it into the browser bundle.
3. Never log configuration values; `/api/health` reports status only.
4. Changing a variable requires a redeploy; existing deployments keep old values.
5. Rotate via the runbook, not by editing git.
